## 1. 背景与目标

### 1.1 要解决的问题

一个家庭通常持有十几份保单，分散在不同保险公司、不同 App 和纸质合同里。家庭成员普遍存在三个问题：说不清家里到底买了什么、保了谁、什么时候到期；遇到事情不知道该找哪张保单，也看不懂免责条款和等待期；每年续保只能被动续，不知道自己的情况变了之后，原有保障是否还够。

### 1.2 产品目标

| 目标 | 可度量的标准 |
|---|---|
| 保单一次上传，档案自动建好 | 核心字段抽取准确率 ≥ 90%，每个字段可点击回到原文位置 |
| 条款问题有据可查 | 每条结论必须附带原文引用，引用通过精确子串校验才展示 |
| 出险时知道能赔多少 | 理赔情景模拟输出分步计算，所有数字由确定性代码计算 |
| 续保前想清楚 | Agent 通过多轮追问补齐需求缺口，输出对比表和客服问题清单 |
| 家庭数据不出家门 | 原始文件与个人身份信息只存 NAS；发给模型的内容全部脱敏 |

### 1.3 非目标

以下内容明确不做，开发过程中不得擅自扩展：

1. 不提供投保、支付、代理购买功能，不对接任何保险公司账户。
2. 不输出「购买某款产品」的结论，续保模块只输出对比事实和待确认问题。
3. 不做医学诊断或核保结论预测，健康告知相关问题一律提示咨询保险公司。
4. 不自动提交理赔，理赔模拟结果仅作估算参考。
5. 不做多家庭、多租户 SaaS。

### 1.4 双重用途

本项目同时承担 Seed-2.1-pro-0915 的案例与测评素材。产品功能按真实家庭需求设计，另设「测评模式」记录每次模型调用的输入输出摘要、token、耗时、工具调用与校验结果，支持同一任务集在多个模型上重放。

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 描述 | 权限 |
|---|---|---|
| 家庭管理员 | 负责上传保单、维护成员、配置模型 | 全部功能 |
| 家庭成员 | 查看与自己相关的保单，使用问答与模拟 | 只读档案 + 问答 + 模拟 |

MVP 只实现单一家庭密码登录，成员级权限放到 v1.1。

### 2.2 核心场景

**场景 A：建档。** 管理员把抽屉里的保单 PDF 和手机拍的纸质合同一次拖进上传区，系统逐份识别、脱敏、抽取字段，管理员在核对页逐项确认，确认后进入保单库。

**场景 B：问条款。** 母亲体检查出甲状腺结节，担心手术是否在重疾险或医疗险范围内。在问答页选择成员后提问，系统给出「可能赔付 / 可能不赔 / 条款中未找到依据」三类结论之一，并在原文页上高亮对应条款。

**场景 C：出险估算。** 父亲骑电动车摔伤住院，花费 3 万元。在理赔模拟页输入事件描述与费用，系统列出可能涉及的保单，按社保报销、免赔额、赔付比例逐步计算估算区间，并提示需要准备的材料类型。

**场景 D：续保。** 管理员的意外险下月到期，今年出差频繁。在续保顾问页发起会话，Agent 追问出行方式、是否出境、出差地点类型、是否有公司团险等，补齐后检索保险公司官网上的同类产品条款，输出逐项对比表和「续保前要问客服的问题清单」。

**场景 E：年度盘点。** 年底导出一份全家保单 PPT，发到家庭群里讨论明年的安排。

## 3. 功能需求

优先级定义：P0 为 MVP 必须交付，P1 为 MVP 应交付、时间不足可降级，P2 为后续版本。

### 3.1 功能总览

| 编号 | 模块 | 优先级 |
|---|---|---|
| F01 | 家庭成员管理 | P0 |
| F02 | 保单上传与解析 | P0 |
| F03 | 本地脱敏 | P0 |
| F04 | 抽取结果核对与确认 | P0 |
| F05 | 保单库与保单详情（原文定位） | P0 |
| F06 | 条款问答 | P0 |
| F07 | 理赔情景模拟 | P0 |
| F08 | 家庭总览（保障时间轴） | P0 |
| F09 | 续保顾问 Agent（意外险） | P1 |
| F10 | 保障覆盖雷达与缺口热力图 | P1 |
| F11 | 全家保单 PPT 导出与回读核验 | P1 |
| F12 | 到期提醒与日历订阅 | P1 |
| F13 | 测评模式与调用日志 | P1 |
| F14 | 条款版本差异对比 | P2 |
| F15 | 3D 家庭保障房子 | P2 |
| F16 | 保单体检长图海报 | P2 |
| F17 | 续保顾问扩展到重疾、医疗、寿险 | P2 |

### 3.2 F01 家庭成员管理

| 项 | 要求 |
|---|---|
| 字段 | 显示名、关系（本人/配偶/子女/父母/其他）、出生年份、性别、职业描述、所在城市、社保类型（职工/居民/无/未知）、头像色 |
| 真实姓名 | 可选填写，仅存本地，用于脱敏时的精确匹配替换 |
| 身份证号 | 不单独存储；解析时出现即脱敏，映射表加密保存 |
| 占位符 | 每个成员自动生成稳定占位符，如 `〔成员A〕`，发给模型时替换真实姓名 |

### 3.3 F02 保单上传与解析

**输入**：PDF（文本型或扫描型）、JPG/PNG/HEIC 照片，单文件 ≤ 50MB，单次 ≤ 20 个文件。多张照片可合并为一份保单。

**处理流程**：

| 步骤 | 执行方 | 说明 |
|---|---|---|
| 1 计算文件哈希 | 代码 | 重复文件直接提示已存在 |
| 2 页面渲染 | 代码 | 每页渲染为 PNG，保存文本层及字符坐标 |
| 3 扫描判定 | 代码 | 文本层有效字符数低于阈值的页走本地 OCR |
| 4 脱敏 | 代码 | 见 F03 |
| 5 文档分类 | 模型 | 判定保险合同、投保单、保单首页、条款、电子发票、批单等页面类型 |
| 6 字段抽取 | 模型 | 输出结构化 JSON，每个字段带页码与原文 quote |
| 7 责任项抽取 | 模型 | 抽取保障责任、保额、免赔额、赔付比例、等待期、免责条款、续保条件 |
| 8 引用校验 | 代码 | quote 必须是该页文本的精确子串（空白归一化后）；坐标由代码回算 |
| 9 数值校验 | 代码 | 金额、日期字段必须能从 quote 中解析出一致的值 |
| 10 进入核对 | 代码 | 生成核对任务，未通过校验的字段标记为「待确认」 |

**抽取字段**：

| 分组 | 字段 |
|---|---|
| 基本信息 | 保险公司、产品名称、保单号（脱敏显示后四位）、险种大类、险种细类、合同类型（长期/短期/一年期） |
| 关系人 | 投保人、被保险人（可多个）、受益人及比例 |
| 金额 | 基本保额、年保费、缴费方式、缴费期、已缴期数（可人工填） |
| 期间 | 投保日、生效日、保障期满日、犹豫期、等待期天数 |
| 续保 | 是否保证续保、保证续保期、续保条件原文 |
| 责任项 | 责任名称、责任类型、保额或限额、免赔额、赔付比例、是否区分社保内外、适用条件 |
| 免责 | 免责条款列表（原文 + 通俗解释） |
| 附加险 | 附加险名称及其责任项，结构同主险 |

**险种分类**：重疾险、医疗险（百万医疗/中高端/小额医疗）、意外险、定期寿险、终身寿险、年金险、增额终身寿、财产险、车险、其他。车险与财产险 MVP 只建档，不参与雷达与模拟。

### 3.4 F03 本地脱敏

| 类型 | 识别方式 | 替换 |
|---|---|---|
| 身份证号 | 正则 + 校验位 | `〔证件1〕`，图片上打码 |
| 手机号 | 正则 | `〔电话1〕` |
| 银行卡号 | 正则 + Luhn 校验 | `〔卡号1〕` |
| 邮箱 | 正则 | `〔邮箱1〕` |
| 成员姓名 | 与 F01 登记的真实姓名精确匹配 | 成员占位符 |
| 保单号 | 字段上下文规则 | `〔保单号〕` |
| 详细地址 | 「地址」「住址」关键词后的同行文本 | `〔地址〕` |

要求：脱敏在文本与图片两个层面同步完成，图片打码位置来自文本层坐标或 OCR 框；映射表使用应用密钥加密保存；界面提供「查看发送给模型的内容」预览；脱敏失败的页不得发送给模型，界面提示人工处理。

### 3.5 F04 抽取结果核对与确认

| 项 | 要求 |
|---|---|
| 布局 | 左侧字段表单，右侧原文页面；点击字段时右侧滚动到对应页并高亮原文 |
| 状态 | 已校验（青色）、待确认（琥珀色）、未找到（灰色）、冲突（红色，多处原文数值不一致） |
| 编辑 | 任意字段可人工修改，修改后标记为人工值并保留模型原值 |
| 确认 | 所有「冲突」字段处理完才能确认入库 |
| 批量 | 同时核对多份时提供队列切换 |

### 3.6 F05 保单库与保单详情

**保单库**：卡片或列表双视图；按成员、险种、保险公司、状态（生效中/等待期/即将到期/已失效）筛选；全文搜索覆盖产品名、责任名称与条款文本。

**保单详情**：顶部为保单摘要卡（被保人、保额、保费、期间、状态徽标）；中部为责任项表格，每项可展开查看原文；底部为免责条款清单与通俗解释；右侧抽屉为原文阅读器，支持页缩略图、缩放与高亮层。

### 3.7 F06 条款问答

| 项 | 要求 |
|---|---|
| 范围选择 | 全家 / 指定成员 / 指定保单 |
| 检索 | 本地全文检索召回相关条款、释义与责任项，按保单聚合后发送给模型 |
| 回答结构 | 结论类别（可能赔付 / 可能不赔 / 视情况而定 / 条款中未找到依据）+ 理由步骤 + 引用列表 + 需要向保险公司确认的事项 |
| 引用校验 | 每条引用做精确子串校验；未通过的引用不展示，若全部引用失败，结论降级为「条款中未找到依据」 |
| 交互 | 点击引用在原文阅读器中定位并高亮 |
| 追问 | 支持同一会话多轮追问，保留引用上下文 |
| 固定提示 | 回答底部固定显示「以保险公司核定为准」 |

### 3.8 F07 理赔情景模拟

**输入**：选择出险成员、事件类型（疾病/意外/身故/其他）、自然语言描述、费用明细（总费用、社保内费用、自费费用，可只填总额）、就诊城市、是否已走社保。

**处理原则**：模型负责从描述中提取事实、判断可能涉及的保单与责任项并给出条款依据；所有计算由代码完成。

**计算规则（代码实现）**：

| 步骤 | 规则 |
|---|---|
| 社保报销 | 用户填写实际报销额；未填时按用户在设置里配置的城市报销比例区间计算上下限，未配置则标注「未知」并按 0 与常见区间给出两个端点 |
| 保单排序 | 同一费用在多份医疗类保单间按「小额医疗 → 百万医疗」的补偿顺序依次抵扣，已补偿部分不重复计算 |
| 免赔额 | 按责任项免赔额扣减，区分年度免赔与单次免赔；多份保单共享免赔额的规则按条款原文，无法判断时两种情况都算 |
| 赔付比例 | 区分经社保与未经社保两档比例 |
| 定额给付 | 重疾、意外伤残、身故类按保额或伤残等级比例给付，不与医疗费用互相抵扣 |
| 等待期 | 出险日期落在等待期内的责任项标记为「等待期内，通常不赔」并排除出合计 |

**输出**：费用瀑布图（总费用 → 社保 → 各保单赔付 → 自付）、分保单结果卡（每项附条款引用）、估算区间、需准备的材料类型、需要向保险公司确认的事项。

### 3.9 F08 家庭总览

| 组件 | 说明 |
|---|---|
| 保障时间轴 | 横轴为时间（默认前后各 18 个月，可缩放），纵轴为成员，每份保单是一条色带；色带上区分等待期段、生效段；色带之间的空档用红色虚线标出；「今天」为一条竖线 |
| 关键数字 | 全家年保费合计、生效保单数、30 天内到期数、存在断保空档的成员数 |
| 待办 | 即将到期、待核对、缺口提示 |
| 快捷入口 | 上传保单、问条款、出险估算 |

### 3.10 F09 续保顾问 Agent

MVP 支持意外险，架构上按险种插件化。

**会话状态机**：

```
START → LOAD_BASELINE → COLLECT_NEEDS → GAP_CHECK ⇄ ASK_USER
      → SEARCH → FETCH_DOCS → EXTRACT_CANDIDATES → COMPARE → REPORT → END
任一状态 → FAILED（记录原因，保留已有成果）
```

| 状态 | 行为 |
|---|---|
| LOAD_BASELINE | 读取当前意外险保单的责任项，作为对比基线 |
| COLLECT_NEEDS | 用户用自然语言描述今年的变化 |
| GAP_CHECK | 对照险种缺口清单，找出未确认的维度，按影响排序 |
| ASK_USER | 每轮最多追问 2 项，每个问题附带「为什么问」的一句说明，提供快捷选项 |
| SEARCH | 使用联网搜索，只接受设置中白名单域名（保险公司官网、监管信息披露平台）的结果 |
| FETCH_DOCS | 后端下载候选产品的条款 PDF，走 F02 的解析与校验流程 |
| EXTRACT_CANDIDATES | 抽取候选产品责任项，价格只从官方费率表或产品页取得，取不到标注「未取得」 |
| COMPARE | 代码按维度对齐基线与候选产品，生成对比矩阵 |
| REPORT | 输出对比表、各维度差异说明（附引用）、客服问题清单、未取得信息清单 |

**意外险缺口清单（初版）**：

| 维度 | 追问示例 | 影响 |
|---|---|---|
| 出行方式 | 出差主要坐飞机、高铁还是自驾？ | 交通工具意外额外保额；驾乘意外 |
| 境外出行 | 今年会去境外出差吗？ | 境外意外医疗、紧急救援 |
| 工作场所 | 出差是在办公室还是工地、厂区、矿区？ | 职业类别，可能影响投保与理赔 |
| 猝死责任 | 当前保单是否包含猝死？是否在意？ | 多数意外险不含猝死 |
| 意外医疗 | 是否有百万医疗险？社保在哪里？ | 意外医疗免赔额与社保外费用 |
| 团险 | 公司是否提供团体意外险？保额多少？ | 避免重复，确认缺口大小 |
| 运动爱好 | 是否潜水、滑雪、攀岩？ | 高风险运动常列为免责 |
| 家庭责任 | 家里是否有房贷、子女教育等负担？ | 身故伤残保额是否足够 |

**防编造约束**：候选产品的每一个事实字段都必须来自已下载并通过校验的文档；来源 URL 必须出现在本会话的检索日志中；搜索工具失败时，报告明确写出「检索未完成」及原因，不得用模型记忆补齐产品信息。

**输出措辞约束**：禁止输出「推荐购买」「最适合」「最划算」等表述；使用「与你的需求更匹配的维度」「续保前建议确认」。

### 3.11 F10 保障覆盖雷达与缺口热力图

| 项 | 说明 |
|---|---|
| 六个维度 | 身故、重疾、医疗、意外、收入中断、养老 |
| 数值 | 每维为「有效保额 / 参考保额」，封顶 120% 显示 |
| 参考保额 | 由用户在设置中为每位成员填写；提供可编辑的默认公式（例如按年收入倍数），界面明确标注「参考值，可自行修改」 |
| 叠加对比 | 最多同时叠加 3 位成员 |
| 缺口热力图 | 行为成员、列为风险类型，颜色表示覆盖程度，点击单元格进入对应保单 |

### 3.12 F11 全家保单 PPT 导出与回读核验

| 项 | 要求 |
|---|---|
| 页面结构 | 封面、全家概览（时间轴）、每位成员一页（保单列表 + 雷达）、年度保费、即将到期、待确认问题 |
| 生成方式 | 版式与数字由代码按模板生成；模型只负责每页的一段中文摘要 |
| 回读核验 | 生成后代码重新读取 PPT，比对所有数字与数据库一致；可选渲染为图片交给模型做视觉检查（文字溢出、遮挡、重叠） |
| 修改 | 用户可用自然语言提出修改（如「把父母两页合并」），修改后再次核验 |

### 3.13 F12 到期提醒与日历订阅

到期前 60/30/7 天、等待期结束、缴费日生成提醒；站内通知；提供 ICS 订阅地址，内网手机日历可订阅。

### 3.14 F13 测评模式与调用日志

| 项 | 要求 |
|---|---|
| 调用日志 | 每次模型调用记录：任务类型、模型 ID、输入 token、缓存命中 token、输出 token、思考 token（若返回）、耗时、工具调用序列、校验结果、是否重试 |
| 模型配置 | 支持配置多个模型端点，界面切换默认模型 |
| 任务集重放 | 命令行工具读取任务集文件，在指定模型上逐个运行，输出 CSV 与 JSON 明细 |
| 故障注入 | 测评模式下可对搜索工具注入超时、空结果、403 |
| 看板 | 按任务类型与模型汇总：成功率、引用通过率、平均 token、平均耗时 |

### 3.15 F14–F17（P2，仅列要点）

F14 条款版本差异：按条款编号与标题对齐新旧版本，逐条文本 diff，模型对每处变化给出通俗说明并附引用。F15 3D 家庭保障房子：成员站在房屋内，每类保障是一面墙，缺口显示为墙上的洞，点击墙面进入对应保单。F16 保单体检长图：一页纵向海报，适合手机分享，内容由数据库数字生成。F17 续保顾问险种扩展：为重疾、医疗、寿险编写缺口清单与对比维度。

## 5. 视觉与交互要求

详细设计令牌见《开发指导手册》第 7 章，本节只规定产品层面的要求。

| 项 | 要求 |
|---|---|
| 风格 | 2026 年主流的柔和磨玻璃层级：流动的环境背景 + 半透明面板 + 清晰的前景信息；浅色与深色两套主题 |
| 气质 | 冷静、可信、有温度。保险是关于家人安全的事，避免金融交易软件式的紧张感和营销感 |

## 7. 模型使用边界

本项目遵循「准确性关键路径用确定性代码，模型负责理解、抽取、解释与对话」的原则。

| 环节 | 模型负责 | 代码负责 |
|---|---|---|
| 解析 | 页面分类、字段与责任项抽取、免责条款通俗解释 | 渲染、OCR、脱敏、引用校验、坐标回算、数值解析 |
| 问答 | 理解问题、选择条款、组织理由 | 检索召回、引用校验、结论降级 |
| 理赔模拟 | 事实提取、责任项匹配、条款依据 | 全部金额计算与区间 |
| 续保 | 缺口追问措辞、检索决策、候选条款抽取、差异说明 | 缺口清单、白名单过滤、URL 溯源校验、对比矩阵对齐 |
| PPT | 每页摘要文字、视觉检查 | 版式、数字、回读核验 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 保险公司官网条款获取困难 | 白名单可配置；取不到时如实标注；续保模块可降级为「手动上传候选条款 PDF」 |
| 扫描件质量差导致抽取失败 | 核对页人工兜底；E2 如实披露下降幅度 |
| 模型输出引用不精确 | 精确子串校验 + 降级展示；提示词中要求逐字摘录 |
| 社保报销规则因地而异 | 不内置规则库，由用户配置或输入实际金额 |
| 合规表述风险 | 输出措辞约束写入提示词与后处理过滤；全站固定免责说明 |
| 磨玻璃效果在低端设备卡顿 | 限制模糊层数；提供「简洁模式」关闭模糊与背景动画 |
